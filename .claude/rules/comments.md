# Comments

Applies to every language.

## Write non-obvious comments

❌ Don't restate what the code shows.
❌ Don't record your thinking process.
❌ Don't narrate the change: why a field was added, what the previous version did, or what a sibling file does. That belongs in the PR description.
❌ Don't explain an absence, unless a reader would otherwise add it back.
✅ Add section comments where they show structure.
✅ Comment a construct that looks wrong but is deliberate, and say why it's needed.
