# jj-octo

A [jj](https://github.com/jj-vcs/jj) subcommand for GitHub that supports stacked pull requests and works in Claude Code cloud sessions.

> [!WARNING]
> `jj-octo` is in early development, and its commands may change. So far it is largely vibe coded.

## Usage

`jj gh --help` documents every command, setting and environment variable. `jj gh <command> --help` documents a command's flags.

## Install

Each [GitHub release](https://github.com/kkom/jj-octo/releases) has a standalone `jj-octo` for macOS on Apple silicon and Linux on x64 and arm64. Or run the [npm package](https://www.npmjs.com/package/jj-octo) with [Bun](https://bun.sh). Both need `jj` 0.41.0 or later on `PATH`.

With [mise](https://mise.jdx.dev), add it to one repository's `mise.toml`:

```toml
[tools]
"github:kkom/jj-octo" = "X.Y.Z"
```

Or to every repository:

```
mise use --global github:kkom/jj-octo@X.Y.Z
```

Then run `jj-octo init` once per checkout. It colocates a jj repository with git, makes GitHub's default branch `trunk()`, and sets the `jj gh` alias.

## In Claude Code cloud sessions

A [cloud session](https://code.claude.com/docs/en/claude-code-on-the-web)'s GitHub proxy can append a "Generated by Claude Code" footer to pull request bodies. In a cloud session, `jj gh submit` by default keeps that footer out of the change's description; `jj-octo.ignore-claude-code-footer` overrides that.

### In an Anthropic-hosted environment

The [GitHub proxy](https://code.claude.com/docs/en/cloud-environments#github-proxy) rejects GraphQL, so `gh pr` fails there. `jj-octo` uses GitHub's REST API, and the proxy's own route to mark a draft ready for review.

### In a self-hosted environment

A [self-hosted runner](https://code.claude.com/docs/en/self-hosted-environments-deploy#use-the-anthropic-git-proxy) started with `--use-anthropic-git-proxy` sends git through a proxy that adds the session creator's GitHub credentials. Point `jj-octo` at the same proxy:

```
jj config set --repo jj-octo.github-auth git-proxy
```

## Development

```
bun install
bun run check    # format, lint, types, tests and build
bun run fix      # regenerated GraphQL types, then format and lint fixes
```

`bun run check` fails where the GraphQL types that `codegen.ts` generates are stale.

To release, run `bun run release:patch`, `release:minor` or `release:major` in a pull request. Once it merges, the `jj-octo` workflow publishes the version to npm and as a GitHub release.

A release must raise the version above its base branch's, to one npm doesn't have. The workflow publishes only the version in the push's last commit. So `CI` fails on every pull request above an unmerged release, and since `main` requires `CI`, they can't merge in one push. In a stack, run `jj gh merge -r` on the release change, then merge the rest.
